# 웹브라우저 요청 흐름

> **개요:** 브라우저 주소창에 도메인을 입력한 뒤 서버 응답을 받아 화면을 그리기까지의 일반적인 순서를 정리합니다.
> 원본 메모의 “TCP/IP, URI, HTTP status 응답” 범위를 벗어나지 않습니다.

## 일반적인 순서

1. **URL 해석**  
   주소창 입력을 스킴(`https`), 호스트, 경로, 쿼리 등으로 나눕니다.
2. **DNS**  
   호스트 이름을 IP 주소로 조회합니다.
3. **연결·TLS**  
   대상 IP·포트로 TCP(또는 QUIC 등) 연결을 맺고, HTTPS면 TLS 핸드셰이크를 합니다.
4. **HTTP 요청**  
   메서드, 경로, 헤더, 본문을 담아 요청을 보냅니다.
5. **서버 처리**  
   서버(또는 앞단 프록시)가 요청을 처리합니다.
6. **응답·렌더링**  
   상태 코드와 본문을 받고, HTML·CSS·스크립트 등을 해석해 화면을 그립니다.
   추가 리소스에 대해 위 과정이 반복될 수 있습니다.

원본이 적어 둔 것처럼, 전송은 TCP/IP 위에서 이루어지고, URI로 자원을 가리키며, 결과는 HTTP 상태 코드로 돌아옵니다.

## 생략될 수 있는 단계

캐시된 DNS·HTTP 응답, 이미 열려 있는 연결(keep-alive), 서비스 워커, HSTS 등이 있으면 일부 단계는 건너뛰거나 짧게 끝납니다.
위 순서는 “처음부터 새로 요청할 때”의 기본 골격입니다.
