# 세션 디스패치 — 태스크 분해 · 모델 선택

> **상태:** `active`  
> **목적:** 작업 **최초 실행**부터 목적·범위·문서·모델을 한 세트로 고정해 **토큰·비용·품질**을 맞춘다.  
> **기대:** 「○○ 구현해줘」한 줄 → **오케스트레이터가 태스크·모델만 분해** → 실행 세션은 **문서 1개 + 적절한 작은 모델**.

---

## 0. 오케스트레이터 (한 줄 요청 → 분해만 · 구현 금지)

사용자가 「가축 CUD 구현」「게이트웨이 배정 목록」처럼 **넓게** 말해도, **첫 세션**은 구현하지 않고 아래만 한다.

1. `domains/{pageId}.md` 있으면 열기 — 없으면 킥오프 필요 여부만 알림
2. 요청이 **공통 CRUD 1세트**인지 **도메인 diff**인지 분류 ([기본셋 §0](../../integration/console-crud-base-set.md#0-포함--제외-한눈에))
3. **다음 미완료 태스크 1개**(또는 직전 완료 태스크의 **짝 QA 1개**)만 고름
4. §3 **모델 티어** 지정
5. §4 **실행 프롬프트** 블록 출력 — 사용자가 **새 채팅·해당 모델**로 붙여넣기

**이 세션에서 읽을 문서 (오케스트레이터):** `domains/{pageId}.md`, [CRUD-IMPLEMENTATION-RUNBOOK](./CRUD-IMPLEMENTATION-RUNBOOK.md) §3 유형표, 본 문서 §3 — **Impl 태스크 md·마스터 가이드 전체는 열지 않음**.

### 오케스트레이터 프롬프트 (복사)

```
오케스트레이터 모드. 코드 수정·구현 금지.

요청: {사용자 한 줄, 예: 가축 Web CUD 붙여줘}

1. pageId 추정 또는 질문 1개만
2. domains/{pageId}.md 진행표 확인 (없으면 킥오프 안내만)
3. 공통 CRUD vs 도메인 diff 구분
4. 다음 1스텝만: Impl 태스크 ID 또는 QA-after ID
5. 모델 티어 S/M/L + 이유 한 줄
6. 실행용 프롬프트 블록 (읽을 pipeline 문서 경로 1개만)

SESSION-DISPATCH.md §3·§4 준수.
```

### 토큰이 줄어드는 이유

| 구간 | 절감 |
|------|------|
| 오케스트레이터 | 구현 컨텍스트·전체 코드 탐색 없음 |
| 실행 세션 (S) | 마스터 문서·다른 메뉴 미로드, 빠른 모델 단가 |
| 실행 세션 (M/L) | 필요한 태스크 md 1개 + 레퍼런스 1~2파일 |
| QA 직후 | 버그 조기 차단 → 대형 재작업 세션 방지 |

**느낌대로 맞음:** 분해·모델 선택이 **구현 전에** 고정되면 세션당 토큰이 **크게** 줄어든다. (자동화는 Cursor 규칙·Automation·수동 「오케스트레이터 프롬프트」 중 택1)

---

## 1. 왜 잘게 쪼개는가

| 없을 때 | 쪼갰을 때 |
|---------|-----------|
| 「가축 페이지 구현해줘」→ 마스터·인덱스·전체 코드 로드 | 「BE-06만」→ 문서 1개 + 레퍼런스 1~2파일 |
| 큰 모델만 안전 | **단순 태스크 = 작은/빠른 모델** 가능 |
| 실패 시 원인·되돌림 범위 큼 | 실패 = 해당 태스크만 재실행 |

**작은 문서** = 컨텍스트 상한이 낮은 모델도 **전문 지시를 빠짐없이** 따를 수 있게 함.

---

## 2. 실행 순서 (디스패치)

```
목적 확인 (공통 CRUD 1세트? 도메인 diff?)
  → domains/{pageId}.md 킥오프 (실행할 태스크 번호만 고정)
  → 세션 1개 = Impl 태스크 1개 OR QA-after 1개
  → 아래 §3으로 모델 티어 선택
  → 프롬프트에 「이 문서만 읽기」 명시
  → domains 시트 [x]
```

**가장 중요한 단계:** 사용자(또는 오케스트레이터)가 **한 번에 하나의 태스크 ID**만 넘기는 것. 모델 선택은 그 다음이다.

---

## 3. 태스크별 모델 티어 (권장)

티어는 Cursor 등에서 **빠른/기본/고성능** 모델에 매핑하면 된다. 팀 합의로 조정.

| 티어 | 쓸 때 | 태스크 예 |
|------|--------|-----------|
| **S (small/fast)** | 패턴 복제·체크리스트·단일 파일 | BE-03, BE-05, FE-02, FE-03, 대부분 `QA-after-*`, `QA-fe-import-check` |
| **M (medium)** | DTO·UI 조립·MAP·i18n | BE-01, BE-04, BE-06, FE-04, FE-05, FE-09, FE-10 |
| **L (large/careful)** | 규칙 많음·도메인 경계·디버깅 | BE-02 (Facade 의존), FE-01a (포털 레지스트리), FE-06~08, **도메인 diff 전체** |

**QA 세션**은 구현보다 한 단계 낮춰도 됨 (S~M) — 문서가 이미 성공 기준을 적어 둠.

**도메인 특화**(가축 탭·분석 BFF·납품 등)는 파이프라인 태스크가 아님 → 별도 킥오프·보통 **L**.

## 4. 세션 프롬프트 템플릿

```
pageId: {pageId}
태스크: {BE-03} 구현만 (QA는 다음 세션).

읽을 문서 (이것만):
- docs/knowledge/frontend/tasks/pipeline/BE-03-controller-list.md

레퍼런스 (필요 시만 열기):
- DeviceProductionWebController

금지: 다른 태스크, 도메인 diff, 전체 마스터 문서.

완료 후: domains/{pageId}.md BE-03 [x]
```

QA 세션:

```
pageId: {pageId} — BE-03 구현 완료. QA만.

읽을 문서:
- docs/knowledge/frontend/tasks/pipeline/qa/QA-after-BE-03-list.md

코드 수정: 검수 실패 시에만.
```

---

## 5. 모델 선택이 잘 되려면 (조건)

1. **킥오프**에서 이번 메뉴에 **실행할 태스크 목록**이 이미 정해져 있음 (`domains/*.md`)
2. **세션당 문서 1개** — 인덱스·런북 전체를 에이전트에 던지지 않음
3. **태스크 문서**에 선행/다음/하지 말 것/검수가 있음 → S 모델도 범위 이탈 적음
4. **짝 QA**로 S 모델 실수를 다음 세션에서 차단

문서만 잘 쪼개도 선택 **가능**해지고, §3 티어 표까지 있으면 **누가/무엇이** 고르기 **쉬워**짐 (사람·자동화 둘 다).
