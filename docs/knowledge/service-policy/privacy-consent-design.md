# 개인정보 처리방침과 동의 설계

웹빌더에서 같은 이메일 주소를 로그인, 결제 안내, 홍보 메일에 사용할 수 있습니다.
저장되는 값은 같아도 사용하는 목적이 다르고, 적용할 처리 근거와 사용자가 선택할 수 있는 범위도 달라집니다.
그래서 개인정보를 정리할 때는 `email` 컬럼 하나를 보는 것보다 **서비스에서 이메일을 언제, 왜 쓰는지**부터 확인하는 편이 좋습니다.

개인정보 처리방침은 수집하는 정보와 처리 목적, 보유 기간, 파기 방법, 사용자 권리 행사 방법 등을 공개하는 문서입니다.
개인정보 동의는 동의를 근거로 처리하는 항목에 대해 사용자의 의사를 받는 절차입니다.
계약 이행 등 별도 근거로 처리하는 항목이 있다면 그 항목과 근거를 구분해 관리합니다.
[개인정보 보호법 제15조, 제22조, 제30조](https://www.law.go.kr/lsInfoP.do?ancYnChk=0&lsId=011357)

## 필수와 선택은 동의하지 않았을 때의 동작을 정합니다

옵트인은 사용자가 직접 선택한 뒤에 적용하는 방식입니다.
옵트아웃은 기본으로 적용하고 사용자가 거부하면 중단하는 방식입니다.
필수 또는 선택이라는 구분은 사용자가 동의하지 않았을 때 어느 단계까지 진행할 수 있는지를 정합니다.

| 상황 | 초기 상태 | 사용자가 선택하지 않으면 |
|---|---|---|
| 특정 기능에 필요한 개인정보 처리를 동의에 근거해 진행합니다. | 미체크 | 해당 기능의 진행 조건을 충족하지 못합니다. |
| 선택적으로 홍보 메일 수신 동의를 받습니다. | 미체크 | 서비스 이용을 계속할 수 있고, 홍보 메일 발송 대상에서는 빠집니다. |

필수 항목 누락 여부는 화면과 API 양쪽에서 검증합니다.
선택 항목은 저장된 동의가 있는 사용자만 발송 대상에 포함되도록 처리합니다.
개인정보 보호법은 선택적으로 동의할 수 있는 사항에 동의하지 않았다는 이유로 서비스 제공을 거부할 수 없도록 정하고 있습니다.
[개인정보 보호법 제22조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335517)

## 현재 상태와 동의 이력을 함께 관리합니다

발송 기능에는 **현재 홍보 메일을 보낼 수 있는지**가 필요합니다.
문의 대응에는 **사용자가 언제 어떤 내용을 보고 동의하거나 철회했는지**가 필요합니다.

예를 들어 동의 목적, 고지 문서 버전, 동의 또는 철회 유형, 처리 시각을 기록할 수 있습니다.
사용자가 홍보 메일 수신을 철회하면 현재 상태를 갱신하고, 이후 발송 작업에서 그 상태를 확인합니다.
철회 전에 발송 대상이 이미 큐에 등록될 수 있다면, 실제 발송 직전에도 수신 상태를 확인해야 합니다.

실제 데이터 흐름을 공개 문서로 옮기는 방법은 [개인정보 처리방침 예시 템플릿](/docs/knowledge/service-policy/privacy-policy-template)에서 볼 수 있습니다.
