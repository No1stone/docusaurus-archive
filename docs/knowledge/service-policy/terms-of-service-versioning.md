# 서비스 이용약관과 버전 관리

웹빌더에는 사이트를 만들 수 있는 개수, 게시 가능한 콘텐츠의 범위, 결제와 해지 후의 처리처럼 사용자와 운영자가 함께 알아야 할 조건이 있습니다.
서비스 이용약관은 이런 **서비스 이용 관계에 적용되는 조건**을 담습니다.
약관을 제시할 때는 사용자가 내용을 알 수 있도록 명시하고, 중요한 내용은 이해할 수 있도록 설명하는 기준도 확인합니다.
[약관의 규제에 관한 법률 제3조](https://www.law.go.kr/법령/약관의규제에관한법률/제3조)

## 약관에 적은 조건을 실제 서비스 동작과 맞춥니다

| 약관에서 다루는 상황 | 구현에서 확인할 동작 |
|---|---|
| 무료 플랜은 사이트 하나를 게시할 수 있습니다. | 두 번째 사이트를 게시할 때 API가 한도를 확인합니다. |
| 해지해도 결제 기간이 끝날 때까지 서비스를 이용할 수 있습니다. | 해지 신청 시각과 실제 이용 종료 시각을 구분해 처리합니다. |
| 이용 기간이 끝나면 게시를 종료합니다. | 관리 화면뿐 아니라 공개 URL에서도 게시 종료 상태가 반영됩니다. |

해지 버튼을 눌렀을 때 바로 사이트를 내릴지, 결제 기간이 끝나면 내릴지는 실제 구현을 바꾸는 결정입니다.
기획 단계에서 기준 시각과 영향을 받는 기능을 정해두면 화면과 API, 배치 작업을 같은 조건으로 검증할 수 있습니다.

## 보여 준 버전과 수락한 버전을 기록합니다

약관을 수정할 때 기존 문서를 덮어쓰면, 나중에 사용자가 수락한 시점의 내용을 확인하기 어렵습니다.
시행일이 있는 버전으로 원문을 보존하고, 수락 기록에는 사용자 식별자, 약관 버전, 수락 시각을 남길 수 있습니다.

예를 들어 사용자가 `v1`을 읽는 동안 `v2`가 시행됐다면, 가입 요청은 화면에 표시한 버전을 함께 보내도록 설계할 수 있습니다.
서버는 해당 버전을 현재 가입에 사용할 수 있는지 검증하고, 새 버전 확인이 필요한 경우 화면에 다시 표시하도록 응답합니다.
개정 때 어떤 사용자에게 무엇을 고지하고 언제 다시 수락을 받을지는 변경 내용과 적용되는 기준에 맞춰 정합니다.

공통 조항과 플랜별 문구는 [서비스 이용약관 예시 템플릿](/docs/knowledge/service-policy/terms-of-service-template)에서 볼 수 있습니다.
