# 소프트웨어 라이선스와 오픈소스 고지

웹빌더를 만들 때 React 패키지, 폰트, 아이콘, Gradle 의존성, 컨테이너 베이스 이미지를 가져다 쓸 수 있습니다.
각 구성요소의 라이선스는 **어떤 사용과 재배포를 허용하고 어떤 조건을 지켜야 하는지** 정합니다.
내 저장소에 `LICENSE`를 두는 일은 내가 공개하는 코드에 어떤 권한을 부여할지 결정하는 일입니다.
외부 구성요소를 포함해 배포할 때는 해당 구성요소에 적용되는 조건도 함께 확인합니다.

## 실제로 전달하는 산출물에서 출발합니다

| 구성요소 | 포함될 수 있는 산출물 | 확인할 내용 |
|---|---|---|
| React 패키지와 폰트 | 브라우저로 내려가는 번들과 정적 파일 | 최종 파일에 포함되는 구성요소와 필요한 고지 |
| Gradle 런타임 의존성 | Spring Boot 실행 JAR 또는 컨테이너 이미지 | 패키징된 라이브러리와 적용 라이선스 |
| 컨테이너 베이스 이미지 | 고객사에 전달하는 컨테이너 이미지 | 베이스 이미지와 함께 전달되는 구성요소의 조건 |

MIT 라이선스는 사용, 수정, 재배포를 폭넓게 허용하면서 복제물이나 소프트웨어의 상당 부분에 저작권 및 허가 고지를 포함하도록 요구합니다.
번들에 포함해서 전달한다면 원본의 고지가 배포 과정에서 빠지지 않는지 확인합니다.
다른 라이선스는 적용 조건과 예외를 각 원문에서 확인합니다.
[MIT 라이선스 원문](https://opensource.org/license/mit)

## 고지는 배포물에서 찾을 수 있어야 합니다

외부 구성요소 고지는 `THIRD-PARTY-NOTICES` 같은 파일에 모을 수 있습니다.
웹에서는 오픈소스 고지 페이지에서 제공하고, 고객사에 전달하는 설치본에는 설치 파일과 함께 동봉하는 방식이 가능합니다.
실제 제공 방식과 포함할 문구는 해당 구성요소의 조건을 따라야 합니다.

의존성을 추가할 때 라이선스를 확인하고, 릴리스를 만들 때 최종 산출물과 고지 내용을 대조하면 누락을 발견하기 쉽습니다.
특히 직접 설치한 패키지가 다른 패키지를 함께 끌고 오는 경우까지 배포 범위를 확인합니다.
