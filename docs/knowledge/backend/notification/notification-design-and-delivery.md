# 알림의 종류와 사용 기술

## 알림의 종류

| 종류 | 사용 상황 | 예시 |
|---|---|---|
| **알림함** | 사용자가 받은 알림을 다시 확인하고 읽음 처리 | 승인 이력, 안 읽은 알림 목록, 모두 읽음 |
| **웹 인앱 알림** | 사용자가 웹 서비스를 이용하는 중에 화면을 갱신 | 상단 알림 벨의 빨간 점, 미확인 개수, 토스트 |
| **모바일 인앱 알림** | 사용자가 앱을 이용하는 중에 화면을 갱신 | 알림 탭 배지, 앱 내부 배너 |
| **모바일 앱 푸시** | 앱이 백그라운드에 있을 때 운영체제 알림으로 전달 | 배송 완료, 새 메시지 |
| **웹 푸시** | 서비스 탭을 닫은 뒤에도 브라우저를 통해 전달 | 브라우저 권한을 받은 사이트 알림 |
| **외부 채널 알림** | 사용자가 등록한 연락처나 업무 채널로 전달 | 이메일, 문자, Teams, Slack 메시지 |
| **장비 이벤트, 명령** | 장비가 상태를 보고하거나 서버가 특정 장비에 명령을 전달 | 농장 게이트웨이 상태 보고, 민팃 기기 설정 갱신 |

## 알림에 사용하는 기술

| 종류 | 기술 | 적용 방식 |
|---|---|---|
| **알림함** | RDB, REST API | 사용자별 알림과 `read_at`을 저장하고 목록, 미확인 상태 조회와 읽음 처리를 제공 |
| **웹 인앱 알림** | SSE(`EventSource`, `SseEmitter`), REST API | 로그인 직후와 SSE 재연결 시 `hasUnread` 조회. 사용 중에는 `notification.changed`를 받으면 배지 갱신 |
| **모바일 인앱 알림** | REST API, 필요 시 SSE, WebSocket | 앱 진입, 복귀 시 알림 상태 조회. 화면을 보는 동안 즉시 갱신이 필요하면 실시간 연결 사용 |
| **모바일 앱 푸시** | FCM, APNs | 기기별 푸시 토큰 등록, 갱신. 알림을 누르면 관련 화면으로 이동 |
| **웹 푸시** | Web Push API, Service Worker | 사용자 권한과 브라우저별 구독 정보를 관리하고, Service Worker에서 알림 표시 |
| **외부 채널 알림** | SMTP, 메일 API, SMS API, 메신저 API | 채널별 Adapter에서 발송하고 결과 기록 |
| **장비 이벤트, 명령** | AMQP, RabbitMQ, Topic Exchange, Direct Exchange | 장비 이벤트는 현장, 장비, 이벤트 종류에 따라 라우팅. 특정 장비 명령은 해당 장비 큐로 전달. 전달이 중요한 메시지는 ACK, 재시도, 중복 처리 적용 |

사용자 알림의 **읽음 상태는 알림함에서 관리**합니다.<br />
예를 들어 승인 알림 한 건을 저장한 뒤, 열린 웹에는 SSE로 배지 갱신을 알리고 모바일에는 앱 푸시를 보낼 수 있습니다.<br />
배포 중 SSE 연결이 끊겨도 화면은 재연결 시 알림함에서 현재 상태를 조회합니다.
