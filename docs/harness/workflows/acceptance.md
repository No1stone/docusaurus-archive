# 구현 전 통과 기준

> **개요:** 이 하네스가 제시하는 통과 가능한 코딩의 기준입니다.
> 구현은 확정된 통과 기준을 받은 뒤에 시작합니다.
> 완료는 테스트 통과만으로 판단하지 않습니다.

## 실행

기본 흐름과 추가 절차는 [`implement.md`](./implement.md)입니다.
모든 역할을 매번 별도 에이전트로 실행하지 않습니다.

통과 기준은 구현 전에 정합니다.
템플릿에 있는 기준은 재사용하고, 이번 작업의 차이만 추가합니다.
분량과 검토는 작업 복잡도에 맞춥니다.
새 계약, 복잡한 정합성, 중요한 설계 변경일 때만 Reviewer가 기준을 봅니다.

## 구현 전 통과 기준 정의

구현 작업은 요구사항에 대응하는 통과 기준을 먼저 정의합니다.
Implementer는 확정된 기준을 전달받은 뒤 개발을 시작합니다.

Master는 요구사항, 작업 범위와 제외 범위를 정리합니다.
Tester는 정상, 경계 및 실패 조건의 테스트 항목과 검증 방법을 작성합니다.
Reviewer는 기준이 요구사항을 충분히 포함하는지, 불필요한 구현 제약을 강제하지 않는지 검토합니다.
Master는 검토 결과를 반영하여 기준을 확정합니다.

각 기준에는 요구사항, 입력 또는 초기 상태, 행동, 기대 결과, 테스트 경계와 검증 방법을 기록합니다.

| 기준 ID | 요구사항 | 초기 상태 또는 입력 | 행동 | 기대 결과 | 테스트 경계 | 검증 방법 |
|---|---|---|---|---|---|---|

실행 가능한 테스트를 먼저 작성하는 경우에는 기대한 동작의 부재로 실패하는지 확인합니다.
컴파일 오류와 환경 문제를 기능 실패의 증거로 취급하지 않습니다.
Spring의 배치와 명명은 [테스트 기본 구조](/docs/knowledge/backend/testing/test-structure)를 따릅니다.
자동화 가능한 기준은 실행 가능한 테스트로 작성합니다.
자동화가 어려운 기준은 별도의 검증 방법과 필요한 증거를 명시합니다.

Implementer는 기준을 충족하도록 구현합니다.
통과를 위해 테스트를 삭제하거나 기대 결과를 약화하지 않습니다.
기준의 오류나 모순을 발견하면 근거와 함께 Master에게 재검토를 요청합니다.

기준 변경 시에는 변경 이유와 영향을 기록하고 관련 테스트를 함께 갱신합니다.
최종 완료는 테스트 통과뿐 아니라 요구사항 충족 여부와 기존 동작의 회귀 여부를 확인하여 판단합니다.
