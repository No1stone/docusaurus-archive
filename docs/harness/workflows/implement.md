# Workflow: Implement

> **개요:** 기본 개발 흐름입니다.
> 역할은 책임의 구분입니다.
> 기본적으로 한 에이전트가 필요한 책임을 수행합니다.

## 기본 흐름

```text
범위와 통과 기준 확인
→ 필요한 규칙 및 템플릿 확인
→ 구현과 테스트
→ 검증
→ 짧은 기록
→ 승인된 경우 커밋
```

통과 기준과 작업별 확인 방법은 [`acceptance.md`](./acceptance.md)입니다.
구현 우선순위는 [`implementer.md`](../agents/implementer.md)입니다.
커밋은 [`git.md`](../context/git.md)입니다.
승인이 없으면 커밋하지 않습니다.

## 별도 에이전트

| 상황 | 별도 에이전트 |
|---|---|
| 익숙한 작업 | 없음 |
| 낯선 저장소 또는 정보 부족 | Scout |
| 복잡한 계약, 중요한 정합성, 중요한 설계 변경 | Reviewer |
| 중요한 사용자 흐름 변경 | QA 및 E2E |
| 재사용할 발견 | 후보만 보고합니다. Curator와 Knowledge, 템플릿 갱신은 사용자가 요청할 때만 합니다 |

별도 에이전트를 실행하지 않아도 요구사항 충족과 회귀 검증은 수행합니다.
필수 검증과 필수 에이전트 실행은 다릅니다.

있는 레시피는 재사용합니다.
새 레시피는 같은 상황이 반복될 때만 제안합니다.
레시피도 이 표를 넘지 않습니다.
