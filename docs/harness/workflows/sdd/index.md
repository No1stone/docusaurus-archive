# SDD 제품 명세 워크플로

**SDD는 대상 저장소의 지침에서 도입 여부를 확인한 뒤 적용합니다.**

제품 명세에는 기능이 어떻게 동작해야 하는지 기록합니다.<br />
구현할 때는 프로젝트 규칙에 따라 필요한 원셋을 참고합니다.

기본 하네스 요청에서도 대상 저장소의 지침을 보고 적용 여부를 판단합니다.<br />
지침에 SDD가 없거나 쓰지 않는다고 되어 있으면 이 흐름을 강제하지 않습니다.

## 명세 찾기

업무 규칙은 `docs/specs/domains/{{domain}}/`에서 찾습니다.<br />
관리자 웹이나 모바일 앱, 외부 연동에서 제공하는 동작은 `docs/specs/applications/{{application}}/`에서 찾습니다.<br />
`{{domain}}`과 `{{application}}`에는 제품에서 사용하는 이름을 넣습니다.

대상 폴더에서 작업에 필요한 인덱스를 고르고, 제목을 보고 관련 문서만 엽니다.

| 확인할 내용 | 인덱스 |
|---|---|
| 제품이 지켜야 할 동작과 통과 기준 | `requirements-index.md` |
| 기능의 구성과 처리 흐름 | `design-index.md` |
| 작업 범위, 진행 상태, 변경과 검증 결과 | `work-index.md` |

## 명세를 바꾸고 작업 결과를 남기기

1. 제품 동작을 추가하거나 변경할 때는 구현 전에 기대 동작과 통과 기준을 요구사항에 반영합니다. 처리 흐름이 바뀌면 관련 설계도 갱신합니다.
2. 작업 범위를 기록하고 관련 요구사항과 설계를 연결합니다. 프로젝트에서 작업 티켓을 관리한다면 해당 티켓도 연결합니다.
3. 구현 후 실제 변경 내용과 검증 결과를 같은 작업 문서에 남깁니다. 새 문서를 추가하면 해당 인덱스에 제목과 링크를 등록합니다.

문서를 처음 만들 때는 [제품 명세 템플릿](/docs/harness/templates/sdd/)의 폴더 구조와 작성 양식을 사용합니다.
