# NULL·UNIQUE·업무 단계

> **상황별 선택:** NULL 허용과 UNIQUE 적용 여부는 각각 판단합니다.
> 대리키를 쓴다고 업무 컬럼 UNIQUE를 일괄 적용하지 않습니다.

화면 진행과 업무 트랜잭션 경계에 맞춰 제약을 고릅니다.

| 상황 | 적용 방향 | 강도 |
|------|-----------|------|
| 회원 생성 후 인증·프로필 연결 전 | 미완성 상태를 저장하도록 필요한 컬럼에 NULL 허용 | 상황별 선택 |
| 단계별 완료 조건 | 애플리케이션에서 검증 | 상황별 선택 |
| 조건부 중복 검사 | 업무 상태·범위에 맞춰 앱에서 처리 | 상황별 선택 |
| 통계 중복 방지 | 집계 대상·집계 시간 등 업무 기준 복합 UNIQUE 검토 | 기본 관례(통계) |

애플리케이션에서만 중복을 검사하는 경우, 동시 요청 처리 방식도 함께 정합니다.

## 이상적 스케치

회원 행은 있으나 인증·추가 프로필이 아직 없어 `profile_id` 등이 NULL인 상태.
가입·온보딩 화면이 끝날 때까지 DB UNIQUE·물리 FK로 막지 않습니다.
완료 단계에서 앱이 연결을 검증합니다.
