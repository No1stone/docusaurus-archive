# 후속 작업

기존 구현은 참고 근거로 보존합니다.
확정한 설계 기준과 과거 구현이 다른 부분은 구분해서 설명합니다.

| 구분 | 확인·작업 내용 |
|------|----------------|
| 기존 구현 대조 | 접두사·접미사, 컬럼 예, Item DTO, JPA 관계, Quartz Batch |
| 예외 확인 | `_log`인데 `UpdatedEntity`인 엔티티, 과거 통계 파티션 정의 |
| 신규 구현 | 공통 파티션 관리 스케줄러 ([파티션 운영](./partition-ops)) |
| 운영 보완 | 백업·복원, 아카이빙, 정합성 점검, 스키마 변경 절차 |
| 참고 자산 | **기존 서비스(비식별):** 사용 예제, 공통코드, 네이밍, JPA·DTO 관례 → [네이밍](./naming), [공통코드](./common-codes), [관계와 조회](./relations-and-dto), [스케치](./examples). **파티션 DDL·운영:** Partner Gateway에서 정리한 예(이 하네스의 [파티셔닝](./partitioning)·[파티션 운영](./partition-ops)) |

이번 아카이브 작업의 중심은 하네스 문서입니다.
be-v1 코드 일괄 수정과 `@Scheduled` 전환은 하지 않습니다.

관계 매핑은 **열어 둔 상태**입니다. 스타일 예만 [관계와 조회](./relations-and-dto)에 두고, 한 가지로 고정하지 않습니다.
