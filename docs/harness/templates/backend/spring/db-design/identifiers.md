# 식별자

> **필수 경계:** 도메인 업무 테이블의 PK 컬럼명은 `id`입니다.
> **상황별 선택:** PK 타입과 발급 방식은 도메인마다 다릅니다.
> **필수 경계(예외):** 공통코드 type·code는 코드 문자열 자연키입니다.

| 대상 | PK 기준 | 강도 |
|------|---------|------|
| 일반 업무·이력·통계 | 대리키 `id` | 필수 경계 |
| 대리키 타입·생성 | 도메인별 선택 (`Long` IDENTITY, 문자열 UUID 등) | 상황별 선택 |
| UUID 문자열 PK | 애플리케이션에서 생성 | 기본 관례 |
| 공통코드·코드 유형 | 코드 자체를 자연키로 사용 | 필수 경계 |

대리키와 업무상 유일성은 별도로 판단합니다.
업무 컬럼에 UNIQUE를 일괄 적용하지 않습니다. → [NULL과 UNIQUE](./null-unique)

별도 `public_id` 컬럼을 두는 패턴은 현재 프로젝트 기본이 아닙니다.
노출 방식은 숫자 `id` 또는 opaque 문자열 PK 중 도메인 정책으로 정합니다.

기존 구현 예(확인분):

| 계열 | 형태 |
|------|------|
| FarmPro형 일부 마스터 | `Long` + IDENTITY |
| 회원·파트너·파일·암호키 등 | 앱 발급 22자 Base64(URL) UUID 문자열 |
| 상태·로그·일별통계 자식 행 | `INT` IDENTITY 대리키 + 부모 `*_id` |
| 공통코드 | 코드 문자열 자연키 (업무성 길이 관례 10, type id는 더 길 수 있음) |
