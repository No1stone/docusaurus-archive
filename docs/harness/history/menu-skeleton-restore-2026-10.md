# 메뉴 골격 복원과 Knowledge 하단 묶음 (2026-10)

> **개요:** 2026-10-25 기준 메뉴 복원 작업 기록입니다.
> 이 문서는 `unlisted`라 사이트 메뉴에 나오지 않습니다.
> 메뉴를 다시 손볼 때 먼저 읽습니다.

## 왜 이 작업을 했는가

한동안 Docs를 Infrastructure, Containers, Development, DevOps 같은 새 최상위 분류로 옮겼습니다.
그 결과 사이드바 감각이 예전과 달라졌고, 원래 원하던 것과 어긋났습니다.

원래 원했던 것은 전체 taxonomy 재배치가 아니었습니다.
Decisions와 Knowledge를 골격으로 유지한 채, 늘어난 글만 찾기 쉽게 묶는 것이었습니다.

## 합의한 방향

1. 메뉴 골격은 이전처럼 **Decisions + Knowledge(+기존 항목)** 를 유지합니다.
2. 전체 재분류는 하지 않습니다.
3. 새로 쌓이는 글만 규칙에 맞게 꽂습니다.
4. 폴더 이름은 **한글, 짧게, 나중에 찾을 때의 질문** 기준으로 둡니다.

## 현재 메뉴 골격

```text
docs/
├── knowledge/
├── architecture/
├── patterns/
├── decisions/
├── experiments/
├── postmortems/
├── harness/
└── history/
```

사이드바는 `autogenerated`입니다.
정렬은 `_category_.json`의 `position`으로 맞춥니다.

## Knowledge 하단 한글 묶음

Knowledge **상단**의 기존 칸(`backend`, `infrastructure`, `networking` 등)은 유지합니다.
**하단**에만 아래 묶음을 둡니다.

| 폴더 | 넣는 글 |
|------|---------|
| `비용` | Savings Plans, t 계열, 인스턴스와 약정 |
| `접속` | Reverse SSH, bastion, 프록시 연결 |
| `로컬 클러스터` | k3d, namespace, ingress |
| `배포` | Blue-Green, 배포 운영 |
| `운영 메모` | 애매한 단일 글 임시 대기 |

규칙:

- 폴더는 넓게, 글 제목은 구체적으로 둡니다.
- 같은 주제가 3편을 넘을 때 폴더를 만듭니다.
- 최상위 메뉴를 새로 많이 만들지 않습니다.
- 애매하면 `운영 메모`에 두었다가 나중에 승격합니다.

## Decisions 한글 그룹

ADR 번호와 공개 URL(`slug`)은 유지합니다.
사이드바만 주제로 묶습니다.

| 그룹 | 예 |
|------|----|
| `문서와 아카이브` | SSOT, Docusaurus, 광고 배치 |
| `플랫폼과 하네스` | MVC, 컨벤션, 하네스 |
| `런타임과 보안` | PHP 런타임 업그레이드 등 |

## Blog

- 시점, 후기, 감상 글은 Blog에 둡니다.
- Blog 메뉴를 깊게 폴더화하지 않습니다.
- 태그만 읽기 쉽게 둡니다.

## 유형 고르는 법

1. 의사결정과 채택 이유 → **Decisions**
2. 설치, 명령, 설정, 운영 절차 → **Knowledge**
3. 시점, 후기, 감상 → **Blog**
4. 애매하면 → Knowledge `운영 메모`

## 이번 복원에서 한 일

- taxonomy 최상위(`infrastructure`, `containers`, `development`, `devops`, `security`, `ai-engineering`)를 걷어내고 이전 골격으로 되돌렸습니다.
- 기존 글은 Knowledge, Decisions, Patterns, Postmortems 쪽으로 되돌렸습니다.
- 공개 URL은 가능한 한 `slug`로 보존했습니다.
- 신규 글은 Knowledge 하단 한글 묶음으로 재배치했습니다.
- Decisions ADR은 한글 주제 그룹으로 나눴습니다.
- `CONTENT_GUIDE.md`와 `.cursor/rules/content-placement.mdc`를 새 골격에 맞게 고쳤습니다.
- 홈과 footer의 메뉴 링크도 Decisions, Knowledge 중심으로 맞췄습니다.
- 복원 스크립트는 `scripts/restore-menu-skeleton.py`에 있습니다.

## 앞으로 메뉴를 점검할 때

1. 이 문서와 저장소 루트 `CONTENT_GUIDE.md`를 먼저 봅니다.
2. 새 최상위 분류를 만들기 전에, Knowledge 하단 묶음으로 해결되는지 봅니다.
3. 파일을 옮기면 기존 공개 URL을 `slug` 또는 redirect로 남깁니다.
4. `docs/harness/**`는 콘텐츠 분류로 옮기지 않습니다.
5. 메뉴가 지저분해지면 폴더를 더 쪼개기보다, 묶음 이름과 글 제목부터 다시 봅니다.
